# Lineage

在编辑器行号栏右键，即可为每一行打开或关闭 Git blame 注释——模仿 JetBrains IDE 的 "Annotate with Git Blame"。

开启后，每行行首显示该行**最后修改的作者、日期（yyyy/MM/dd）和提交摘要**；鼠标悬停可查看短 hash、作者、完整日期时间和完整 commit message。未提交的行显示为"未提交"。

## 使用方法

1. 在编辑器**行号**上右键，菜单中选择 `Annotate with Git Blame`
2. 菜单项出现 `✓` 前缀表示已开启；再次点击关闭
3. 开关状态全局生效并持久化，重启 VSCode 后自动恢复
4. 命令面板不提供入口（仅行号栏右键菜单）

## 运行要求

- 系统已安装 `git` 并在 PATH 中
- 需要信任工作区（Trust Workspace）：受限模式下扩展不加载（`capabilities` 中声明不支持未信任工作区）
- 文件须位于 git 仓库中；未跟踪文件、非 git 目录、untitled 文件等场景静默跳过（日志见输出面板 "Lineage" 通道）

## 查看调试日志

默认只输出 Info 及以上级别。排查防抖、缓存命中、git 调用等问题时需要 Debug 级日志：

1. 打开输出面板（`查看 → 输出`），右上角下拉选择 **Lineage** 通道
2. 点击面板右上角的**设置日志级别**按钮，选择 **Debug**

设置对当前窗口生效，重新加载窗口后恢复默认。

## 已知限制

1. VSCode 没有开放在行号栏中绘制文本的 API，注释只能以 `before` 装饰注入到代码前面，代码因此整体右移。这是有意接受的限制。
2. 菜单的"勾选"效果由标题中的 `✓` 字符模拟，并非原生勾选框。
3. 开关状态在多个窗口之间不会实时同步：`globalState` 是共享的，但没有跨窗口的变更事件，其他窗口在重新加载后才会生效。
4. 在终端中执行 commit 等外部 git 操作后，已缓存的注释不会自动更新；文档内容变化、重新打开文件或重新开关功能后才会刷新。
5. 东亚字符的宽度采用近似计算，在少数字体下列可能不完全对齐。
